공문 레지스터는 **AI 티 제거 + 공문·보고서 형식 교정**을 함께 한다. 대상은 공문·기안문·보고서·계획서·결과보고서·성과보고서·회의자료처럼 □ ○ - 기호의 개조식으로 쓰는 행정 문서다.

등급: **[hard]** = 결정적 검사기(`scripts/check_gongmun.py`)가 막는다. 0건이 될 때까지 고친다. **[soft]** = 검토할 것. 고칠 근거가 분명할 때만 고친다. **[치명]** = 검사기는 못 잡지만 하나라도 있으면 완성본이 아니다.

우선순위: 사실·의미·확정 수준 보존 > 사용자 지시·지정 서식 > [hard] > [soft] > 간결함.
**압축해서 뜻이 틀어지면 압축을 푼다. 길이를 맞추려고 핵심 정보를 지우지 않는다.**

## G-1. 항목 길이 [hard: 120자 초과 금지]

- **한 항목 한 정보, 두 줄 안.** 공백 제외 45~55자가 권장, 25~70자가 허용 범위다. [soft]
- **90자를 넘으면 나누는 것을 검토한다.** [soft]
- **120자를 넘는 항목은 반드시 나눈다.** [hard] 따옴표 안 인용은 길이에서 뺀다.
  - 예외: "①…, ②…, ③…" 또는 "A(수치), B(수치), C(수치)" 같은 **대등 나열**만 허용. 종속절을 겹친 항목("…하였으며, …하였고, …인 가운데 …")은 예외가 아니다.
- **주장은 짧고 근거는 길다.** 상위(□·1단)는 판단만 40자 안팎, 하위(○·-)는 수치·조건을 붙여 50자 안팎.
- **3단 밑으로 내려갈 내용은 ※(조건·예외)·*(수치 부연)으로 보낸다.**

### 긴 항목을 나누는 순서
1. 주어와 서술어를 찾는다. 생략돼 해석이 갈리면 원문 안에서 보충한다.
2. 한 항목에 서로 다른 주체나 판단이 있는지 확인한다.
3. 사실·해석·요청이 함께 있으면 기능별로 분리한다. 사실은 위에, 해석·요청은 각각 별도 항목으로.
4. 연도·단계가 이어지는 서술은 **연도별·단계별 하위 항목**으로 나눈다.
   - 예: "2023년 A로 시작해 2024년 B로 확장, 2025년 C, 2026년 D로 운영함"(300자대)
     → `- 연도별 확장: 2023 A → 2024 B → 2025 C` / `- 2026 D`
5. 분리한 항목 사이에 꼭 필요한 '다만·반면·특히'는 남긴다.
6. **원래의 조건·예외·부정·단위·역접('~하되', '~이나')이 모두 남았는지 대조한다.** 자르는 대상은 수식어·중복·군더더기이지 주체·시점·수치·조건·부정이 아니다.

## G-2. 종결 [hard: 개조식 항목 끝 '-다/-습니다' 금지]

- **개조식 항목 끝에 '-다', '-습니다', '-요'를 쓰지 않는다.** [hard] (인용문 제외)
- 원문이 '~함/~임/~음'으로 쓰고 있으면 그 말끝을 유지한다. 서술형으로 바꾸지 않는다.

| 항목의 기능 | 종결 | 예 |
|---|---|---|
| 사실·경과 | 동작성 명사 (운영·도입·확대·구축·제출) | 2026년 섬머스쿨 기간으로 이동 운영 |
| 사실·수치 | 숫자·단위·괄호 | 2·3학년 36명(10팀) 참가 |
| 분석·판단 | -ㅁ (나타남·보임·예상됨·있음) | 만족도가 절반 수준으로 나타남 |
| 제언·요청 | 필요, 검토 필요, 건의, 요청 | 협약기관 확대 검토 필요 |
| 진행 상태 | ~ 중, ~ 예정, ~ 계획 | 2027년 1월 운영 예정 |

- **명사형으로 끝내되 문장 성분은 남긴다.** 주체와 시점을 항목 앞에 두고, 목적어·부사어 조사를 뜻이 흐려질 만큼 빼지 않는다.
- **사실을 '발표하였음'으로 늘리지 않는다**("발표"로 끝). '-ㅁ'은 판단에 쓴다.
- **호응이 깨진 압축은 고친다.** "시설이 설치" → "시설이 설치됨".

## G-3. 확정 수준 보존 [치명]

| 근거의 상태 | 쓸 표현 | 하면 안 되는 변환 |
|---|---|---|
| 사실 확인 | 확인 / 동작성 명사 | 출처 불명 내용을 '확인'으로 격상 |
| 관찰된 관계 | 동반 증가 / 관련성 관찰 | 곧바로 '기인'으로 변경 |
| 제한된 해석 | ~로 해석됨 / ~ 가능성 | 한계를 지우고 '입증'으로 |
| 추계·예측 | ~로 추정 / 전망 | 실적처럼 '달성'으로 |
| 계획·예정 | 추진 예정 / ~ 계획 | '완료'·'시행'으로 |
| 미결 | 미정 / 담당 미정 | 임의로 담당·일정 채움 |

## G-4. 어휘 [soft]

- **애매·과장어**: 대체로·대부분·많은·상당한·다양한·적극(적으로)·지속적으로·원활·제고·획기적 → 원문에 수치·근거가 있으면 그것으로, 없으면 지우거나 그대로 둔다(지어내지 않는다).
- **번역투(지움)**: ~에 있어서 → ~에서, ~을 필요로 하다 → ~이 필요, ~에 의해 ~되다 → 능동으로, ~시키다, ~되어지다.
- **군더더기(지움)**: ~에 대하여/~에 대한, ~을 통하여 → ~로, ~의 경우, ~함에 있어, ~라고 할 수 있음.
- **어려운 한자어(치환)**: 금번→이번, 상기→위의, 동법→이 법, 당해→그(해당), 익일→다음 날, 제반→여러.
- **추상명사는 주체와 행동으로** — 단, 그 사실이 원문에 있을 때만. "협조체계 강화" → (원문에 있으면) "두 부서가 매주 목록 공유".
- **같은 개념 같은 용어.** '이용자·고객·수혜자'로 바꿔 부르지 않는다.
- **약어는 첫 등장에 풀이** — 권장 사항. 원문에 풀이가 없으면 지어내지 말고 작성자 확인에 남긴다.
- 행정 정식 명칭·사업명·기관명·교과명은 쉬운 말로 바꾸지 않는다(T-1과 같은 원리).

## G-5. 표기 [soft — 알림만]

날짜 `2024. 12. 10.`, 기간 `2024. 11. 15.~22.`, 시간 `15:20`, 금액 만 단위(천 원 단위 금지), 증감 `△`·`%p`.
**편집 시 원문 표기는 사용자 요청 없이 바꾸지 않는다.** 규범과 다르면 바꾸지 말고 요약 블록의 '작성자 확인'에 남긴다.

## G-6. 기호·구조 [soft]

- □ ○ - (또는 1. 가. 1)) 체계는 **원문 체계를 그대로 따른다.** 한 문서에 한 체계.
- 계층은 3단까지 권장. 넘으면 알림만 한다(양식이 고정된 경우가 많음).
- 하위 항목이 하나뿐이면 상위와 합치는 것을 검토한다.
- 편집하면서 「(참여) …」 같은 **괄호 라벨 머리말을 새로 만들어 붙이지 않는다.** 원문에 있던 괄호 라벨은 유지한다.
- 순접 접속어(그리고·또한·그래서)로 항목을 시작하지 않는다. 항목 머리 접속어는 다만·반면·한편·특히·향후·최근만.

## G-7. 하지 않는 것 [치명]

- 원문에 없는 수치·인용·담당자·날짜·비용·사례·기관명 생성
- 조건·부정·예외·역접 삭제로 뜻이 바뀜
- 제안·추정·계획을 확정·완료·달성으로 격상, 또는 확인된 사실을 '검토'로 약화
- 원문과 다른 수치를 설명 없이 사용
- 완성 본문에 점검 결과·수정 이유·자리표시자 설명을 섞음 (요약 블록에만 쓴다)
- 표·인용문 안(따옴표·낫표 안 글자 포함)·URL·기사 제목·법령 조문·고유명사 수정
